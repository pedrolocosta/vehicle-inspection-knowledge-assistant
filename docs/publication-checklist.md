# Publication checklist

Before making a GitHub repository public:

- Verify ownership and usage rights for the project name, logos, presenter likeness, photos, and generated assets. The provided reference images are intentionally excluded.
- Keep private communications, their transcripts and attachments, and company procedures out of GitHub. Do not import them into the repository, including its history.
- Remove PTs, ITs, internal spreadsheets, customer details, vehicle identifiers, staff details, credentials, and licensed standards unless explicitly authorized for publication.
- Public availability is not the same as permission to redistribute a full document. Prefer a precise official reference or link, and review reproduction rights before committing a copy.
- Confirm that any normative statement uses a current official source and has documented RT review; keep pending interpretations visibly marked.
- Keep engineering and portfolio documentation in American English; write Pedro's client-facing text, normative material, and RT interpretations in Brazilian Portuguese.
- Review the Git history, not only the latest files, for accidentally committed material.
- Choose an explicit software and content license only after deciding which rights can be granted.
- Replace any portfolio claims of implementation or performance with actual reproducible evidence.

This checklist is a publishing workflow, not a claim that the repository has already been posted to GitHub.
